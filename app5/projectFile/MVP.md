# 魔物娘戰場 — MVP 設計文件

> 最後更新：2026-04-21
> 定位：自動戰鬥 + 資源投資 + 卡牌組合，無即時微操

---

## 遊戲定位

玩家扮演指揮官，在六角棋盤戰場上：
- 小隊**全自動戰鬥**，玩家不直接控制移動或攻擊
- 戰鬥中賺取資源，投資**從者**和**Buff**強化小隊
- 佔領更多區域 → 更多資源 → 加速滾雪球 → 推倒敵方主堡

核心樂趣：**組合的快感** + **時機判斷的緊張感**，而非微操

---

## 核心迴圈

```
戰鬥自動進行
    ↓
賺取靈力（擊殺 + 佔領節點）
    ↓
從運輸帶抓從者牌 / Buff 牌
    ↓
把 Buff 疊在從者上（暫存區）
    ↓
時機對了 → 召喚進小隊（補充護盾層）
    ↓
小隊更強 → 推進更多節點
```

## 運輸帶系統（核心新機制）

### 兩條帶

| 帶 | 內容 | 特性 |
|---|---|---|
| 從者帶 | 從者牌（各兵種） | 決定補哪種護盾層 |
| Buff 帶 | Trait 牌（各種行為加成） | 疊在暫存區的從者上 |

### 手牌規則

- 兩條帶各有獨立手牌上限（暫定各 N=4）
- 可手動丟棄不要的牌
- **手牌滿 → 該帶停止推進**（壓力機制，不丟就卡住）
- 打牌消耗靈力，不能無限出

### 暫存區

- 抓到的從者牌放在「暫存區」等待
- 從 Buff 帶抓到的 Trait 牌可以疊加在暫存區的從者上
- 疊好後選擇時機召喚進場上小隊
- 召喚有短暫延遲（隊長死亡時中斷、從者消失）

### 牌池結構（A+B 混合）

```
基本池（永遠存在）
  → 穩定度，提供基礎從者和 Trait
  
自訂池（戰前帶入）
  → 玩家選帶哪些卡影響機率偏向或保證出現
  → 例：帶「衝鋒特化卡」→ Charge Trait 機率提升 + 一張保底
```

### 卡牌設計哲學

- **高CP低上限**：便宜、門檻低、前期穩定輸出（例：`ATK+30` 的 Buff）
- **低CP高上限**：需要條件疊加才爆發（例：`Splash + 5層疊加後爆炸`）

## Trait 系統（行為抽象層）

行為不綁定兵種，而是以 **Trait** 的形式疊加在從者上。

### 概念

```
騎兵從者：預設帶 [Charge]
重甲從者：預設帶 [Block]
攻城從者：預設帶 [Splash]

Buff 牌可以給任何從者加 Trait：
  → 步兵 + [Charge] = 衝鋒步兵
  → 弓兵 + [Splash] = 爆炸箭
  → 任意 + [LifeSteal] = 吸血型
```

### MVP Trait 清單

| Trait | 效果 |
|---|---|
| `Charge` | 移動後首擊傷害加成，目標 ATB 清零 |
| `Splash` | 攻擊時對目標周圍格造成濺射傷害 |
| `Block` | 一定機率格擋近戰傷害 |
| `Pierce` | 攻擊無視目標一定比例防禦 |
| `LifeSteal` | 攻擊吸取一定比例傷害為隊長回血 |
| `Taunt` | 強制成為優先攻擊目標（提高 blockPriority） |

## 屬性傷害系統

取代相剋表，改用三種傷害屬性：

| 屬性 | 說明 | 天生兵種 |
|---|---|---|
| 物理 | 普通近戰攻擊 | 步兵、騎兵、重甲 |
| 穿透 | 無視部分防禦 | 弓兵、攻城 |
| 魔法 | 對高防有效，靠 Buff 賦予 | 特殊 Buff 才有 |

每個單位有三條抗性值：`physDef / pierceDef / magDef`

```
傷害 = ATK - target[damageType + 'Def']
```

## 小隊結構

```
小隊
  ├── 隊長（Captain）× 1
  │     有真實 HP，歸零 → 敗退 → 等待復活
  │     ATB 滿 → 自動攻擊
  │     有 SP 條，SP 滿可觸發特殊技
  │
  └── 從者（Follower）× 0~3（護盾層）
        有護盾 HP，優先承傷
        也有 ATB，可獨立出手攻擊
        死亡後消失，不隨隊長復活
        靠戰中召喚補充
```

### 隊長復活

- 敗退後等待 `reviveDelay` tick 後裸體復活
- 復活後無從者，需花靈力重新召喚

## 地圖系統

### 地圖模板（Map Template）

地圖由模板生成，模板控制結構，RNG 填入細節。預設四種模板：

| id | 名稱 | 路線數 | 每路佔點 | 森林 | 高地 |
|---|---|---|---|---|---|
| `standard` | 標準戰場 | 3 | 1 | 稀疏 | 有 |
| `fortress` | 要塞戰場 | 3 | 2 | 稀疏 | 有 |
| `jungle`   | 密林戰場 | 3 | 1 | 密集 | 無 |
| `blitz`    | 閃擊戰場 | 3 | 1 | 無   | 無 |

未來可支援 2 路、4 路模板（架構已備好）。

### 路線系統（Lane）

路線數量不寫死，由模板的 `lanes[]` 定義，存入 `GameState`：

```ts
LaneDef = {
  id:       string      // 路線 ID（'top', 'mid', 'upper_mid'…）
  label:    string      // 顯示名稱（'上路', '上中路'…）
  row:      number      // 地圖 r 值
  sequence: string[]    // AI 依序前往的 zone 節點列表
}
```

小隊面板的路線按鈕、AI 路徑規劃，全部從 `state.lanes` 動態讀取。

### 區域（Zone）

佔領點為多格共享一個 `ZoneState`，格子以 `zoneId` 標記所屬區域：

```
ZoneState = { zoneId, nodeType, team, captureHp, cells[], facility? }
MapCell   = { pos, terrain, passable, building?, zoneId? }
```

- `cells[]`：隸屬於此區域的所有格子
- `facility`：未來區域建築的掛載點（防禦塔、急救站…）
- 一個區域只有一份 captureHp，不會發生「半格已佔」的矛盾狀態

## 地圖節點

| 節點 | 佔領後效果 | 可建造 |
|---|---|---|
| 前哨站 | 靈力 +產出 | 防禦塔 / 急救站 / 採集站 |
| 軍營 | 靈力 + 生產加速 | 徵兵所 |
| 高地 | 射程兵種 +1 射程 | 瞭望台 |
| 城門 | 阻擋，摧毀才能進下一區 | 無 |
| 敵主堡 | 佔領即勝利 | — |

---

## 勝敗條件

| | 說明 |
|---|---|
| 勝利 | 佔領敵方主堡 |
| 失敗A | 計時器歸零（敵方持續施壓） |
| 失敗B | 玩家主堡 HP 歸零 |
