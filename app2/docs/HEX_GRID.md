# 六角格戰場設計文件

## 為什麼選擇六角格

競技場類戰鬥（3 對 3 小隊 vs 敵人組合）使用六角格而非方形格，有以下理由：

### 方向語言更豐富

方形格有 4 個正交方向 + 4 個對角線，但對角線移動距離不一致（斜走 ≈ 1.41 格），
造成「是否算相鄰」的曖昧地帶。

六角格有 6 個等距方向，每個相鄰格距離完全一致，適合：

- **背刺系統**：「背後 3 格」定義清晰，不會有對角線灰色地帶
- **保護位**：面朝方向明確，前方 3 格 vs 後方 3 格
- **投射物軌跡**：直線射程沿六軸延伸，自然沒有 45° 偏移問題

### 更自然的「包圍感」

六角格的移動範圍呈六角形，比方形格（菱形展開）更接近直覺上的「可到達範圍」。
三個玩家角色站成三角形時，可以形成真正的包圍圈，而不是方形格裡難以配合的 L 形站位。

## 坐標系統

本專案使用 **odd-r offset + axial 雙軌系統**。

### Axial 坐標（q, r）

用於：
- 距離計算
- 範圍查詢（移動範圍、攻擊範圍）
- 引擎邏輯

```
距離公式：hexDistance(a, b) = (|dq| + |dr| + |dq+dr|) / 2
```

六個方向向量（axial）：
```
(+1, 0)  右
(+1,-1)  右上
( 0,-1)  左上
(-1, 0)  左
(-1,+1)  左下
( 0,+1)  右下
```

### Offset 坐標（col, row）

用於：
- 格子生成（矩形網格迴圈）
- 視覺佈局

轉換規則（odd-r，pointy-top，奇數行右移）：
```
offset → axial:   q = col - floor(row / 2),  r = row
axial  → offset:  col = q + floor(r / 2),    row = r
```

### 像素坐標（pointy-top）

```
x = size * √3 * (q + r/2)
y = size * 1.5 * r
```

SVG 多邊形頂點（以中心為原點，從 -30° 開始逆時針）：
```typescript
for i in 0..5:
  angle = 60 * i - 30  (degrees)
  x = size * cos(angle)
  y = size * sin(angle)
```

## 戰場設計

### 尺寸建議

MVP 戰場：**9 列 × 7 行**（63 格）

- 3v3 小隊在 9×7 不會太擠
- 移動範圍 4 的角色可以跨越場地約一半
- Boss 戰加大到 11×9 也可行

### 初始站位

```
         [Enemy A] [Enemy B]
[Player A]                   [Enemy Boss]
[Player B]
[Player C]
```

左側 col=0~1 為己方出生區，右側 col=7~8 為敵方出生區。

### 地形層（未來擴充）

| 地形 | 效果 |
|---|---|
| 普通地面 | 無修正 |
| 高地 | 投射物射程 +1，受攻擊 -10% |
| 障礙 | 不可進入，可提供掩護 |
| 毒霧 | 每回合受 DoT，可被驅散 |
| 陷阱格 | 進入時觸發效果（Bind, Slow 等）|

## 移動與攻擊範圍規則

### 移動範圍

- 範圍 = `unit.move`（axial 距離）
- 排除：已有單位站立的格子
- 未來：地形額外移動消耗（如障礙需消耗 2 移動）

### 近戰攻擊範圍

- 原地不動的近戰攻擊：相鄰 1 格（hexDistance = 1）
- 衝刺攻擊（如狼人「裂牙突進」）：移動 + 攻擊同時，範圍 = move + 1

### 遠程攻擊範圍

- 射程 = 武器 baseRecovery 相關參數（待定）
- 建議先用固定射程（如鳥妖 = 4 格）
- 受高地加成

### 打斷判定

打斷不依距離，而依「是否有效命中」+ 武器的 `baseInterrupt` 值。

## 背刺邏輯（待實作）

六角格的背刺定義：

目標面向方向（0~5，六個方向之一）決定「前方三格」和「後方三格」。

```
前方三格（面朝右：direction=0）:
  (+1, 0), (+1,-1), (+1,+1) → axial 的 3 個「前半側」方向

後方三格:
  (-1, 0), (-1,+1), (-1,-1)
```

攻擊者從後方三格發動攻擊時，觸發「背刺加成」。
