## 掃描 #3：線上對戰路徑 ✅（已重導向）

**架構釐清**：CLAUDE.md 寫的 Supabase + `api/rooms/` 已封存（`_backup_supabase/`），目前活的是 **peerjs P2P**（[src/stores/connection.ts](../app/src/stores/connection.ts) 341 行）。Scan #3 第一次跑掃到封存的虛幻路徑，重派後針對 P2P 路徑做。

### 驗證後的真議題（依「友善 PVP 對戰」context 評估）

| 優先 | 類別 | 位置 | 風險 | 議題 | 修法 |
|---|---|---|---|---|---|
| **P1** | A 身份驗證 | [connection.ts:110-120](../app/src/stores/connection.ts) | med | 任何知道 room id 的人都能 connect，host 用 `_conn = c` 覆寫，後到者「踢掉」前一個合法 guest。room code 雖然 6 字母 ≈ 10 億組合，但 `Math.random()` 非密碼學安全 | 加 secret/token（join 時夾帶，host 驗證後才 `_conn = c`）；用 `crypto.getRandomValues()` 產 roomId |
| **P1** | B 版本盲信 | [connection.ts:158-159, 270-285](../app/src/stores/connection.ts) | med | Guest 收到 `MsgInit/Ack/Push` 直接覆寫 `localVersion = msg.version`，不檢查單調遞增。Host 端 reduce 也沒驗 `expectedVersion`，所以非惡意情境下也可能因「自己 reduce 過但收到舊 push」造成狀態漂移 | Guest 加 `msg.version > localVersion` 守門；action 帶上 `expectedVersion`，host 不符直接拒絕 |
| **P2** | D 重連 | [connection.ts:139-146 vs 221-227](../app/src/stores/connection.ts) | med | Guest 連線逾時 15s、action 等回應 10s；但 host 端對「guest 卡死」無上限。host 一直 hold `_pendingActionResolve` UI 凍結 | 加 host 側 30s heartbeat / kick 邏輯，或對 `_conn` 加超時 |
| **P2** | D localStorage | [connection.ts:334-339](../app/src/stores/connection.ts) | low | 硬關瀏覽器後 `chess_connection` 殘留；若同 room id 被別人重用，舊 tab 可能幽靈重連 | persist 加 timestamp，過期自動清；status 變 error 時主動清 |
| P3 | D TURN | [connection.ts:23-31](../app/src/stores/connection.ts) | low | PEER_CONFIG 只有 STUN 沒 TURN，嚴格 NAT 下連不上（公司網路、行動網路常見） | 加 TURN 伺服器（如 metered.ca 免費層或自架 coturn） |

### Agent 誤判 / 過度評估（已剔除或降級）

- **「duplicate action 無防禦」**：peerjs reliable channel (line 149 `reliable: true`) 用 SCTP，協議層已處理重傳去重；UI 層 `isSendingAction` 也防雙擊。非真 bug。
- **「Host 是 source of truth，guest 無法驗證作弊」**：此為架構設計選擇而非 bug；友善 PVP 場景可接受。如未來要做 ranked / 競技模式才需要 server-side authoritative。
- **「genId 熵不足、必須 UUID」**：6 字母 32 字元集 ≈ 10 億組合對「友善開房分享 code」夠用；只是 `Math.random` 應改 crypto-safe。
- **「建議回到 Supabase」**：是 trade-off 不是 bug。Supabase 帶來 server-side 驗證但也加運維與成本，由產品方向決定。

**結論**：P2P 路徑在「朋友間開房對戰」用途下健康度 ~6/10。沒有立即玩家可見的 bug，但身份驗證 + 版本盲信兩條是「對方惡意連入或網路漂移」會踩雷的地方。**P1 兩條建議在引擎 bug 修完後接著處理**。
